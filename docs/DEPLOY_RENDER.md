# Deploying TruthLens + Sync ID on Render (free plan)

One Docker web service, zero hosting cost.

```
Internet --HTTPS--> Render --> TruthLens  0.0.0.0:$PORT   (public: UI + /api/*)
                                  └─HTTP--> Sync ID 127.0.0.1:8001  (internal only, bearer-token registration)
```

Files: `Dockerfile`, `deploy/start.sh` (starts both, exits if either dies so Render restarts it),
`deploy/syncid_key.py` (signing key from a secret), `render.yaml` (Blueprint).

## Deploy / redeploy
1. Render dashboard → **New → Blueprint** → pick `naveenn108786-web/TruthLens-SyncID`, branch `deploy/render`.
2. Render reads `render.yaml` (plan `free`, Docker, health check `/api/health`) and generates the secrets.
3. Apply. The first build takes ~5–10 min. Every push to `deploy/render` redeploys automatically
   (or **Manual Deploy → Deploy latest commit**).
4. Optional: set `ANTHROPIC_API_KEY` in the service's Environment tab. Without it the rule-based fallback is used.

## Environment
| Variable | Purpose |
|---|---|
| `SYNCID_SIGNING_SEED` | **Secret.** 32-byte seed = the Sync ID Ed25519 private key. Generated by Render, never in Git. Keeps the same public key across restarts; TruthLens pins it (`issuer_trust: key_pinned`). Rotating it invalidates earlier signatures. |
| `SYNCID_API_TOKEN` | Secret shared by TruthLens and Sync ID; direct registration on the internal port needs it. |
| `TRUTHLENS_ADMIN_TOKEN` | Secret for admin endpoints (`POST /api/registry/reset` with header `X-Admin-Token`). |
| `TRUTHLENS_PUBLIC=1` | Public mode: admin lock, rate limit, HSTS. |
| `TRUTHLENS_MAX_UPLOAD_MB=50` | Upload cap per request (lowered from 200 for the 512 MB instance). |
| `TRUTHLENS_RATE_LIMIT=20` | POST requests per client IP per minute (global cap ×10). |

## What is lost on restart (free plan has no persistent disk)
Everything under `/tmp/truthlens-data` is wiped when the instance restarts, redeploys or **spins down after ~15 min idle**:
uploaded evidence, case history, PDF reports, custody log, originals registered by users, and Sync ID registrations.

What survives: the code, the demo samples, the 3 demo registry originals (re-seeded on every start) and the Sync ID
**signing key** (from the secret). So all four demo cases work after every cold start, and a signed Sync ID record
saved before a restart still has a valid signature under the same public key, but the registry no longer holds it,
so `verify` by Sync ID returns "not found". Register and verify in the same session.

Cold start: the first request after idle takes about 30–60 s while Render wakes the instance. Open the URL a minute before judging.

## Security notes
- Sync ID's port 8001 binds to 127.0.0.1 only; registration also requires `SYNCID_API_TOKEN`.
- Public Sync ID registration exists only through TruthLens (`/api/syncid/register`, 25 MiB cap, rate limited). This is intentional for the demo.
- Uploads are validated by content (magic bytes + decode check); evidence is served with content-derived types, and
  non-media is served as `text/plain` with `nosniff`, so uploaded HTML cannot execute. Case/artifact paths are confined to the case folder.
- Unhandled errors return a generic message; tracebacks go to the Render log only. Both services run as an unprivileged user.

**Remaining limitations:** no user accounts, so every visitor can see the case history and uploads of other visitors
(do not upload private material); the rate limit is per process and trusts `X-Forwarded-For`; the Sync ID issuer key is
self-published (pinning proves integrity, not identity); free instances have 512 MB RAM and shared CPU, so large videos are slow.

## Run the container locally
```bash
docker build -t truthlens .
docker run --rm -p 10000:10000 -e SYNCID_SIGNING_SEED="$(python -c 'import secrets,base64;print(base64.b64encode(secrets.token_bytes(32)).decode())')" truthlens
# open http://localhost:10000  ·  health: /api/health
```
